# Raspberry Pi coding setup

The Pi (Raspberry Pi 5) needs the same shell/editor/agent setup as the
workstation, minus the desktop and the tools that only make sense with a
keyboard and a Mac. This is a platform target like `mac`, `arch` and `wsl`,
not a cross-platform rework of `common`.

## Machine

- Raspberry Pi OS 13 (Debian trixie), aarch64, kernel 6.18.
- Login shell ships as bash.
- No brew, no asdf, no node. vim, git, python3, curl, make and docker present.

## Targets

- `apt/pkglist.txt` + `apt` — install Debian packages, mirroring
  `pacman/pkglist.txt` / `pkg`.
- `node` — install Node LTS with `n`, plus `pure-prompt`.
- `rpi` — `apt node` then the supported config subset, then `chsh` to zsh.

`rpi` composes `zsh vim nvim tmux z git worktrunk pi`. Excluded because they
don't fit a headless Pi: `vscode`, `session-leds`, `claude`, `browser`,
`ghostty`, `sway`/`konsole`/`mako`/`wallpapers`. `common` is untouched so the
other platforms don't shift.

## Node

apt's nodejs is 20.19.2, below the 22.19 `pi/bin/pi` requires. Rather than a
second system Node, the manager's Node is the only one: `n` with
`N_PREFIX=~/.n` installs a real binary outside `~/.asdf`, so the wrapper's
"first node outside asdf" rule keeps working with no change. `n` needs no
subshell or per-directory switching, which suits a box that just runs one
Node.

`~/.zshrc` gains a guarded block putting `$N_PREFIX/bin` on PATH. Make recipe
shells are bash and don't read `.zshrc`, so the `npm` target prepends the same
dir for the targets that need it.

## worktrunk binary

`make worktrunk` only symlinked config; on the Mac the `wt` binary comes from
brew. Linux gets the upstream `aarch64-unknown-linux-musl` release (static, so
no glibc or Rust toolchain needed), installed to `~/.local/bin` alongside
`git-wt`. Guarded by `command -v wt`, so brew's copy still wins on the Mac.

## Details a Pi target forced out

- `chsh -s zsh` — the shell config is symlinked but the login shell isn't zsh.
- `prompt pure` expects `pure-prompt`; on the Mac that's brew's `pure`. Installed
  from npm into `~/.npm-global`, which the existing fpath line already points at.
- `.zshrc` sources `~/lib/z.sh` unguarded, so `z` is part of the set.
- `xz-utils` in the package list: `n` extracts node's `.tar.xz`.
